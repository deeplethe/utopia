# 权限、安全与审计

人工登录会话与机器 API Token 是两套独立凭证；知识体系角色与平台管理员权限也分别判断。

## 成员角色

| 角色 | 权限 |
| --- | --- |
| Owner | 管理成员、API Token、知识体系生命周期和高风险操作 |
| Editor | 执行文档、抽取、本体、术语、实例和审阅等内容操作 |
| Viewer | 只读浏览知识体系 |

平台管理员负责用户和全局运行设置，但不会自动替代知识体系内的业务角色判断。

## API Token

每个 Token 只属于一个知识体系，拥有独立的名称、Scope、过期时间和吊销状态。Token 只通过 `Authorization` Header 发送，不应进入 URL、日志或源码仓库。

新 Token 以 SHA-256 哈希用于认证，并保存加密密文以允许 Owner 主动再次查看。吊销时删除密文，且立即停止对外访问，不影响其他 Token 或浏览器会话。

## SPARQL 防护

对外查询只接受 `SELECT` 与 `ASK`，拒绝 `SERVICE`、`FROM`、`GRAPH` 和所有更新操作。查询数据集固定为 Token 所属知识体系，并受最大行数和文本长度限制。

## 模型与隐私

只有用户选中的 chunk 与有界本体上下文会发送到管理员配置的模型端点。模型不会得到不受限制的数据库、文件系统或其他知识体系访问权。

## 审计

图修改、审阅决定、回滚、Token 管理和发布都会留下操作者、时间、动作摘要与相关对象。发布制品不可变，文件带 SHA-256，可用于交付校验。

## 生产建议

- 启用 HTTPS 与 `COOKIE_SECURE=true`；
- 修改默认管理员密码和数据库密码；
- 在反向代理配置请求大小、限流和访问日志；
- 备份数据库、RDF 存储、制品和 Token 加密密钥；
- 限制模型端点出站网络范围。
