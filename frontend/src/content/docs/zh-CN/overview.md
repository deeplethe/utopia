# 产品概览

OntoPilot 是面向本体工程的自托管治理工作台。它把 PDF、Word、表格、Markdown、CSV 和纯文本等源材料，转化为**可审阅、可追溯、可版本化并可稳定服务**的知识体系。

## 为什么需要 OntoPilot

大模型擅长从文本提出结构候选，但生产可用的本体还需要边界控制、来源证据、人工裁决、版本语义和稳定交付。OntoPilot 不把一次模型调用包装成“自动建模”，而是把模型输出视为待治理提案。

- **治理优先**：候选必须经过角色判定、确定性守卫和人工审阅。
- **三层分离**：TBox、SKOS 术语和 ABox 分层存储、协同治理。
- **证据优先**：语句可回到文档、chunk、原文片段、任务和提示词快照。
- **发布不可变**：工作区可持续修改，生产应用固定读取发布快照。
- **自托管**：关系元数据、RDF 图、源文件和发布制品默认保留在部署环境内。

## 工作区与发布版本

工作区面向工程师持续编辑，发布版本面向下游应用稳定消费。两者之间由四类审阅队列与质量门禁隔开，因此应用不会意外读取尚未处理的候选或半完成修改。

| 区域 | 主要用户 | 是否可变 | 典型用途 |
| --- | --- | --- | --- |
| 工作区 | Owner、Editor、Viewer | 是 | 抽取、编辑、审阅、验证 |
| 固定发布版本 | 业务应用、数据服务 | 否 | REST、RDF、SPARQL 查询 |
| `published` 别名 | 需要跟随最新版本的应用 | 指向可变，内容版本不可变 | 灰度或始终读取最新发布 |

## 适用场景

- 从规范、手册、报告与业务文档持续建设领域本体；
- 需要严格区分类、术语、实例与事实，并保留逐条证据；
- 多人协作审阅，要求变更历史、回滚和发布门禁；
- 通过 REST、RDF 或 SPARQL 向其他系统稳定供数。

> OntoPilot 的目标不是替代本体工程师，而是把重复抽取、证据整理、候选检查和版本交付自动化，让人工集中在真正需要判断的地方。
